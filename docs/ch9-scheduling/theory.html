Four kinds of scheduling

An operating system makes scheduling decisions at four levels. Each level answers one question. The long-term and medium-term schedulers decide how many processes compete; the short-term scheduler decides which one runs on the processor now.

A process moves through states. It is new when it is created, ready when it is waiting only for the processor, running while the processor executes it, blocked while it waits for an event such as the end of an I/O operation, suspended when it has been moved out of main memory to disk, and exit when it has finished.

WordMeaning
DispatcherAnother name for the short-term scheduler: it gives the processor to a ready process.
SwappingMoving a process out of main memory to disk (swap out), or back in (swap in).
Degree of multiprogrammingThe number of processes in the system at the same time.
InterruptA signal that stops the running program so the operating system can react, for example the clock or an I/O device.
Batch jobA job that runs without a user waiting at the screen.
I/O-bound processA process that spends most of its time waiting for I/O and uses the processor only briefly.
SemaphoreA counter that processes use to signal each other (it can wake a waiting process).
TypeThe decision it makesNotes
Long-termWhether to add a new program to the pool of processes to be executed (admit it as a new process).Controls the degree of multiprogramming. The policies FCFS, round robin, SPN, SRT, HRRN, Feedback and Priority are all short-term scheduling policies.

Scheduling criteria

A scheduling policy is judged by criteria. User-oriented criteria describe what a user or a single process notices. System-oriented criteria describe how well the whole system uses the processor. Performance-related criteria are numbers that are easy to measure; the other criteria are qualities that are hard to measure.

CriterionMeaning
Turnaround timeTime from when a process is submitted until it completes: execution time plus all waiting. Suits batch jobs.
Response timeFor an interactive request: time from submitting the request until the response starts to arrive.
DeadlinesWhen completion deadlines are given, meet as many of them as possible.
PredictabilityA job runs in about the same time and cost whatever the load on the system.
ThroughputThe number of processes completed per unit of time.
Processor utilisationThe percentage of time the processor is busy.
FairnessProcesses are treated the same, and no process suffers starvation (a process waits a very long time, or forever, and never gets the processor).
Enforcing prioritiesHigher-priority processes are favoured.
Balancing resourcesKeep the resources of the system busy.

The measures

  1. Turnaround time Tr = finish time − arrival time.
  2. Normalised turnaround Tr/Ts, where Ts is the service time. 1 means no waiting at all; a large value means the process waited a long time compared with what it needed.
  3. Waiting time = Tr − Ts (finish − arrival − service).

Selection function and decision mode

Each short-term policy has a selection function: the rule that picks the next process. It can use w, the time spent waiting so far; e, the time spent executing so far; and s, the total service time the process needs. The time a process still needs is s − e. Because s is not known in advance, policies that use s need an estimate of it.

Each policy also has a decision mode. In a non-preemptive policy a running process keeps running until it ends or blocks itself. In a preemptive policy the operating system may interrupt the running process. It can decide this at three moments: when a new process arrives; when an interrupt moves a blocked process to Ready; or at a clock interrupt at the end of a time quantum (a fixed slice of processor time, written q, that a process may use before the scheduler decides again).

First come, first served (FCFS)

First come, first served (FCFS, also called FIFO) keeps one ready queue. A new process joins the back. When the running process ends or blocks, the process at the front (the one that has waited longest, max[w]) runs. There is no preemption.

FCFS has minimum overhead and no starvation, but a short process that arrives behind a long one waits a long time, so its Tr/Ts is large. FCFS also treats I/O-bound processes badly.

Round robin (RR)

Round robin gives each process a time slice, the quantum q. The running process is preempted by a clock interrupt when its quantum ends and goes to the back of the ready queue; the process at the front runs next. A process that ends before its quantum is used up simply leaves.

Two rules for ties

If a new process arrives at the same time as the running process's quantum ends, the new process joins the queue first, and the preempted process goes in behind it. If the quantum ends and no other process is ready, the same process keeps running with a new quantum (A runs from 0 to 2 in the q = 1 diagram).

Shortest process next (SPN)

Shortest process next (SPN) is non-preemptive. Each time the processor becomes free, it picks the ready process with the shortest expected service time, min[s]. Short processes are chosen before longer ones that arrived earlier.

Two risks: the service times must be estimated, and a long process can starve if shorter processes keep arriving.

Shortest remaining time (SRT)

Shortest remaining time (SRT) is the preemptive version of SPN. It picks min[s − e], the least time left. It checks again whenever a new process arrives: if the newcomer needs strictly less time than the running process has left, the newcomer preempts it.

Equal times

When the newcomer needs exactly the same time as the running process has left, there is no preemption: the running process continues. (A past exam question uses this rule.)

Assumed

In the textbook example, at time 10 B and D both need 5 more units. B, the earlier arrival, runs first. The course material never decides such a tie, so this order is assumed.

SRT gives good turnaround for short processes, but it needs estimates of s, has the overhead of tracking e, and long processes can starve.

Highest response ratio next (HRRN)

Highest response ratio next (HRRN) is non-preemptive. When the processor becomes free it works out, for each ready process, the response ratio

Response ratio

R = (w + s) / s, where w = time spent waiting so far = (now − arrival time) and s = service time.

A process that has just arrived has w = 0, so R = 1.

The process with the highest R runs. A short process gets a high R quickly, so HRRN favours short processes; but R of a long process grows the longer it waits, so it gets its turn. There is no starvation.

Feedback (multilevel feedback queues)

Feedback (multilevel feedback) does not need to know service times. It uses several ready queues (RQ0, RQ1, ...; RQ means ready queue): RQ0 has the highest priority. A new process enters RQ0. Each time a process is preempted it moves down one queue, so a process that has used a lot of processor time moves down to the lower queues. Short processes finish while they are still high up.

Feedback rules for this question

  • Quantum: q = 1 in every queue.
  • A new process joins the back of RQ0 (RQ means ready queue).
  • The scheduler runs the front process of the highest queue that is not empty. Each queue is FCFS.
  • Preemption happens only when a quantum ends. A process that arrives in the middle of a quantum waits.
  • If a process uses its whole quantum and another process is waiting, it moves down one queue. If nothing else is waiting, it stays and starts a new quantum.
  • There is no lowest queue: the number of queues is not limited, so a process that is preempted always moves down one more queue (the textbook rule).

With q = 1 every queue has the same short quantum. A long process moves down to a low queue. There it gets only one unit at a time. So it can wait a long time. It can starve if new processes keep arriving.

With q = 2i the lower queues get longer quanta (1, 2, 4, 8, ...). A long process gets more time each time it is chosen. So it is less likely to starve when many new processes arrive.

On the textbook workload the numbers favour q = 1 on both measures: mean Tr 10 against 10.60, and mean Tr/Ts 2.29 against 2.63. No new processes keep arriving in this workload, so the starvation risk of q = 1 does not show here.

Priority scheduling

With priority scheduling each process has a priority number. In COS 122 a lower number means a higher priority (1 is the highest). The scheduler always picks the ready process with the highest priority.

In non-preemptive priority, the running process keeps running until it finishes. In preemptive priority, a new arrival with a strictly higher priority preempts the running process; the preempted process waits in the ready set and is chosen again when it has the highest priority.

Low-priority processes can starve if higher-priority processes keep arriving. The remedy is a dynamic priority, called ageing: the priority improves the longer the process waits.

The effect of the time quantum

The quantum q controls round robin (and Feedback):

  • A small q gives short processes a quick turn, so their response time is good, but there are many more process switches, and each switch costs overhead.
  • A large q means fewer switches. If q is at least as long as the longest service time, no process is ever preempted, and RR becomes FCFS.
  • A good q is a little longer than a typical interaction, so most interactive requests finish within one quantum.
  • Average turnaround depends on the workload: on the workload below it is higher for q = 5 than for q = 2, and lowest for q = 10.

Other textbook topics (short)

Estimating the service time. SPN, SRT and HRRN need s. The system can estimate the next burst from past bursts. A simple average gives every past burst the same weight. Exponential averaging uses Sn+1 = a·Tn + (1 − a)·Sn, where Tn is the last actual burst, Sn the last estimate and 0 < a < 1. A larger a follows changes in behaviour faster.

Virtual round robin adds an auxiliary queue for processes that return from I/O, so I/O-bound processes are not treated badly. Fair-share scheduling shares the processor between groups of users rather than single processes. Traditional UNIX scheduling uses multilevel feedback with round robin in each priority queue, and recomputes priorities every second from recent processor use.

S3 = 0.8×4 + 0.2×6.8 = 4.56.
